# Урок 1. Найди истекающую подписку в собственном бинарнике

**Цель:** научиться находить строку лицензии, определять, где она используется, и узнавать, как несколькими проверками управляется PRO-доступ.

## Факты о лаборатории

- **AtlasLab** — учебное приложение для iOS, сборка arm64.
- Локальная логика находится в `App/LicenseCore/LicenseCore.c`; она попадает в бинарник `AtlasLab`.
- Начальная дата — `2023-12-31T23:59:59Z`.
- Активность вычисляется как `account_enabled == 1 && plan_code == 2 && expiry_epoch > now_epoch`.
- При смене только первых 4 цифр строки на `2099` дата станет будущей.
- Режим "Имитация сервера" — это отдельный JSON, не реальный API.

## Практика 1: строка

1. Открой в IDA Pro файл `AtlasLab-arm64-MachO` из сборки GitHub Actions. Если IPA ещё не собран, открой `bin/LicenseCore-arm64.o` — это учебный объект ARM64 Mach-O, а не полное приложение.
2. Открой окно **Strings** (часто **Shift+F12** либо **View > Open subviews > Strings**).
3. Найди `ATLAS_TRAINING_LICENSE_LOCAL_V1`.
4. Затем найди `2023-12-31T23:59:59Z`.
5. По Xrefs (обычно `X` на строке) посмотри, из какой функции читается дата.

На практике скомпилированный Swift/ARM64 может быть намного менее очевидным, чем исходный C. Работай с маленьким учебным объектом до получения полноценного IPA.

## Практика 2: разбор функции

В полном ARM64 исполняемом файле найди `lab_license_seed_expiry` и `lab_has_local_entitlement` (если символы не удалены сборкой). Изучай Xrefs на тренировочную строку и функцию, а не полагайся только на название символа.

Попытайся объяснить условия:

```c
if (account_enabled != 1) return 0;
if (plan_code != 2) return 0;
if (expiry_epoch <= now_epoch) return 0;
return 1;
```

## Практика 3: изменение собственной сборки

Для собственной лаборатории (не стороннего приложения) изучим изменение **только четырёх байтов года** в строке `2023` -> `2099`, работу **Edit > Patch program**, сохранение изменённого Mach-O и повторную подпись IPA.

Важно: изменение в IDA **не означает** автоматического изменения установленного приложения. Для запуска на iPhone нужен правильно собранный и подписанный пакет. Без локального или удалённого Mac проще всего сначала изучить patch в `LicenseCore-arm64.o`, а для повторной сборки полного IPA использовать GitHub Actions.

## Практика 4: почему сервер — другой случай

Проверь режим "Имитация сервера": fixture JSON содержит срок `2035` (в будущем), но `active: false`. Дата может быть будущей, но PRO не активирован. Это учебная модель; в реальных системах серверный статус не должен доверяться локально изменяемому JSON.

## Контрольные вопросы

- Чем отличается строка в `__cstring` от функции, которая её использует?
- Почему можно заменить `2023` на `2099` без изменения длины строки?
- Почему аккаунт с неподтверждённым статусом не откроется только от изменения даты?
- Почему после патча исходная цифровая подпись iOS перестаёт подходить?
